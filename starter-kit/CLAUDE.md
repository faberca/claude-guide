# 프로젝트 기본 지침

- 한국어로 쉽게 답하고 결론과 핵심 이유부터 쓴다.
- 답변 길이는 질문에 맞춘다. 중요한 조건·실패·미완료는 생략하지 않는다.
- 긴 문서는 기존 정본을 먼저 찾아 갱신한다. 짧은 질문마다 파일을 만들지 않는다.
- 사실·추정·제안을 구분하고 중요한 주장에는 근거를 연결한다.
- 로컬 사실은 파일·코드·로그로 확인한다. 바뀔 수 있는 외부 정보는 현재 출처를 확인한다.
- 기존 구현과 사용자 변경을 읽고 요청 범위에 필요한 부분만 수정한다.
- 구현 후 바뀐 동작에 맞는 검사를 실행하고 실제 결과와 미검증 범위를 보고한다.
- 파일 생성·설정 반영·실제 동작 확인을 서로 구분한다.
- 개인정보·토큰·비밀번호를 공유 문서나 커밋에 넣지 않는다.
- 파일 삭제·외부 발송·커밋·배포는 현재 요청과 승인 범위를 따른다.
- 같은 접근이 반복 실패하면 원인을 확인하고 다른 방법을 시도한다.
- 조사·문서·큰 변경의 상세 절차가 필요할 때만 `.claude/references/guide-workflows.md`의 해당 절을 읽는다.
- 스킬은 해당 작업을 요청받았을 때 선택한다. 모든 지침과 참고자료를 매번 읽지 않는다.

프로젝트의 목적·실행 명령·검증 방법은 실제 파일을 확인한 뒤 필요한 만큼 추가한다.
